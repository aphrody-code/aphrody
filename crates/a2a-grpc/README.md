# a2a-grpc

## What is `a2a-grpc`?

`a2a-grpc` is the gRPC protocol binding for the AGNTCY a2a/v0.4 protocol.
It uses `tonic` under the hood (gRPC over HTTP/2) to plug both the client
and the server halves of the A2A stack into the canonical
`A2aService` proto service generated by `a2a-pb`. The crate gives you a
`Transport` implementation for the client side and an `A2aService` adapter
for the server side, with bidirectional conversion between native A2A types
and protobuf payloads handled through `a2a_pb::pbconv`. Published and
imported under the same name: `a2a-grpc` / `a2a_grpc`.

## Install

```toml
[dependencies]
a2a-grpc = { version = "0.2" }
a2a = { package = "a2a-lf", version = "0.2" }
a2a-client = { package = "a2a-client-lf", version = "0.1" }
a2a-server = { package = "a2a-server-lf", version = "0.3" }
tonic = "0.12"
```

## Quick start

```rust
use a2a_client::A2AClient;
use a2a_grpc::GrpcTransport;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    // Bare host:port is auto-prefixed with http:// for interop with other SDKs.
    let transport = GrpcTransport::connect("localhost:50051").await?;
    let _client = A2AClient::new(transport);
    Ok(())
}
```

## Public API

Source of truth: `crates/a2a-grpc/src/lib.rs`. The crate exports
`GrpcTransport` and `GrpcTransportFactory` from the `client` module, and
`GrpcHandler` from the `server` module. The `errors` submodule is public for
`a2a::A2AError <-> tonic::Status` conversion helpers. Under
`feature = "rustls"`, the crate re-exports `tokio_rustls::rustls` so
downstream consumers can configure TLS material without pulling rustls
twice.

## TLS

TLS is wired through `rustls` with the `ring` crypto provider, matching the
rest of the aphrody stack. As called out in CLAUDE.md section 7, rustls 0.23
will panic with `No provider set` at runtime unless
`rustls::crypto::ring::default_provider().install_default()` is invoked
before the first `reqwest::Client::new()` or `tonic::transport::Channel`.
The `rustls-tls` default feature transitively enables the right plumbing on
both client and server; the `rustls` feature additionally pulls in
`tokio-rustls`, `tonic-tls`, `rcgen`, and `rustls-pemfile` for advanced
scenarios (custom roots, mutual TLS, self-signed dev certs).

## Cross-platform

Linux (cible #1) and Windows are fully supported. The crate emits a
`compile_error!` on `wasm32` targets because `tonic` / `mio` require
OS-level TCP networking. For WASM consumers use `a2a-client` with
`RestTransportFactory`; native gRPC-Web is not yet bridged through this
crate.
