# Go binaries / artifacts inventory

Every Go binary or Go-derived artifact found in aphrody's RE corpus. aphrody
compiles none of these; it documents their contract and (for the language
server) reproduces it in Rust. No secrets are reproduced here.

## Binaries

| Artifact | Path | Size | Language | Role | How aphrody interacts |
|---|---|---|---|---|---|
| `language_server.exe` | Antigravity install on host (resolved at runtime, not vendored) | ~136 MB | Go (Codeium `codeium_common_go_proto`, `exa.*_pb` gRPC) | Antigravity compute engine: owns cloud auth + all upstream traffic; serves self-signed cert-pinned HTTPS gRPC on `127.0.0.1` | Spawned & driven by [`crates/antigravity-sdk/src/local_ls.rs`](../../crates/antigravity-sdk/src/local_ls.rs) (feature `local-ls`); resolved via `$ANTIGRAVITY_HARNESS_PATH` / `$CODEIUM_LANGUAGE_SERVER_BIN` / sibling `resources/bin/` / `PATH` |
| `localharness` | `google/antigravity/bin/localharness` inside the `google-antigravity` PyPI wheel | not in repo (shipped per-platform in the wheel only) | Go (pre-compiled) | Local agent harness for the `google-antigravity` Python SDK: spawned as a subprocess, length-prefixed protobuf handshake over stdin/stdout, then a local WebSocket `ws://localhost:<port>/` carrying protobuf-as-JSON | Not used by aphrody. Documented as the SDK's transport; a Rust port (strategy A) would spawn it the same way. See [`docs/research/antigravity-sdk-analysis.md`](../research/antigravity-sdk-analysis.md) §2-3 |
| `agy.exe` / Antigravity CLI launcher | Antigravity install (Electron shell entry) | n/a (Electron/JS shell, **not** Go) | TypeScript/Electron | Thin shell that spawns/supervises the Go `language_server.exe` | The launch logic was RE'd from `languageServer.js` and reproduced in `local_ls.rs` |

Notes on `localharness`:

- Declared as wheel package-data in
  [`libs/antigravity-sdk-python/pyproject.toml`](../../libs/antigravity-sdk-python/pyproject.toml)
  lines 67-71: *"Include the pre-compiled Go binary in the wheel. The release
  script places the platform-appropriate binary at
  `google/antigravity/bin/localharness` before building each wheel."* and
  `[tool.setuptools.package-data] "google.antigravity.bin" = ["*"]`.
- **Not present in the local clone** (the `google/antigravity/bin/` directory
  does not exist on disk) — confirming it is delivered only inside built wheels,
  exactly as the analysis notes
  ([`docs/research/antigravity-sdk-analysis.md`](../research/antigravity-sdk-analysis.md)
  §0/§6.4 "binaire `localharness` non versionné dans le dépôt").
- Discovery order in the SDK: `$ANTIGRAVITY_HARNESS_PATH` →
  `importlib.metadata` (wheel) → `importlib.resources` →
  `shutil.which("localharness")`
  ([`docs/research/antigravity-sdk-analysis.md`](../research/antigravity-sdk-analysis.md) §3).

`language_server.exe` vs `localharness`: the desktop IDE's
`language_server.exe` is the *full* Codeium engine (gRPC, OAuth, Cascade); the
SDK's `localharness` is a *narrower* Go harness exposing the agent loop over a
local WebSocket with a Gemini API key. The Rust `resolve_binary` treats either
name as a valid `$ANTIGRAVITY_HARNESS_PATH` target
([`crates/antigravity-sdk/src/local_ls.rs`](../../crates/antigravity-sdk/src/local_ls.rs)).

## Confirmed Go-free corpus

- **bxc reference** (`var/data/bxc-ref/`): Bun + TypeScript + Zig + Rust.
  `package.json` declares `packageManager: bun@1.3.14`; no `go.mod`, no `*.go`
  files; `bin/bxc` is a Bun-built binary. The only `go`-substring matches in its
  Markdown are English words ("go", "Google"), not Go code. **No Go usage.**
