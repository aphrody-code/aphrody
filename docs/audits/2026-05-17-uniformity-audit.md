# Aphrody repo uniformity audit (2026-05-17)

Triggered by user directive: "uniformise tout le repo aphrody pour garder une
bonne cohésion, maintenabilité et lisibilité pour les AI".

Context: commit `817de9254` (16-agent surpass batch, +30 200 lines) introduced
style drift between crates written by parallel agents. This audit enumerates
the residual inconsistencies and the planned remediation.

## Repo overview

- **Languages**: Rust (workspace, 30 member crates), TypeScript (Bun scripts +
  packages/* forks), Markdown docs, PowerShell helpers under `scripts/`.
- **Build system**: Cargo (workspace at root) + Bun (root `bun.lock`, `package.json`).
- **Platforms**: Linux Ubuntu 26.04 (#1) > Windows 11 Canary (#2) > WASM (#3).
- **Toolchain**: nightly pinned via `rust-toolchain.toml`.

## Category 1 — Cargo.toml uniformity

### 1.a Inline `version = "1.0.0-canary"` in workspace.dependencies (root)

`C:/src/aphrody/Cargo.toml:420-423` — `mrx-core`, `mrx-detect`, `mrx-audit`,
`mrx-watch` declare `version = "1.0.0-canary"` inline. These are path-deps for
internal crates and the version literal duplicates `[workspace.package].version`.
**Fix**: drop the inline `version = ...`, keep only `{ path = "..." }` (path
deps don't need versions when not published).

### 1.b Inline `version = "1.0.0-canary"` in member crate deps

- `C:/src/aphrody/crates/backend/Cargo.toml:27` —
  `base = { path = "../base", version = "1.0.0-canary" }`. Same as 1.a.

### 1.c Per-crate `Cargo.lock` files (workspace owns the root lock)

- `C:/src/aphrody/crates/agui-bridge/Cargo.lock`
- `C:/src/aphrody/crates/aphrody-voice/Cargo.lock`
- `C:/src/aphrody/crates/aphrody-voice-stt/Cargo.lock`
- `C:/src/aphrody/crates/gemini-runtime/Cargo.lock`

**Fix**: delete. These were generated by ad-hoc `cargo build` runs inside the
crate dir before they were added to the workspace.

### 1.d Stray per-crate `target/` directories

- `C:/src/aphrody/crates/agui-bridge/target/`
- `C:/src/aphrody/crates/aphrody-voice/target/`
- `C:/src/aphrody/crates/aphrody-voice-stt/target/`
- `C:/src/aphrody/crates/aphrody-wasm/target/`
- `C:/src/aphrody/crates/cli/target/`
- `C:/src/aphrody/crates/gemini-runtime/target/`

**Fix**: delete (already covered by root `.gitignore`).

### 1.e Versions kept intentionally inline (NOT a bug)

The a2a-* crates publish to crates.io with independent semver:

- `crates/a2a/Cargo.toml:4` — `version = "0.3.0"` (a2a-lf)
- `crates/a2a-client/Cargo.toml:4` — `version = "0.1.16"` (a2a-client-lf)
- `crates/a2a-pb/Cargo.toml:4` — `version = "0.1.8"` (a2a-pb)
- `crates/a2a-grpc/Cargo.toml:4` — `version = "0.2.2"` (a2a-grpc)
- `crates/a2a-server/Cargo.toml:4` — `version = "0.3.0"` (a2a-server-lf)
- `crates/a2a-slimrpc/Cargo.toml:10` — `version = "0.1.11"` (excluded crate)

These are upstream-mirrored from AGNTCY and must keep independent versions so
crates.io publication doesn't break consumers. **Leave as-is.**

### 1.f `[workspace]` table in member crates

- `crates/a2a-slimrpc/Cargo.toml:7` — self-contained `[workspace]` stub. This
  is intentional and documented above the table: the crate is EXCLUDED from
  the root workspace pending an upstream fix, and the stub keeps tools that
  walk crate dirs (cargo-machete, cargo-vet) able to parse it. **Leave as-is.**

### 1.g `[lints.rust]` / `[lints.clippy]` / `[lints.rustdoc]` in member crates

None found outside `a2a-slimrpc` (which is excluded). All members already use
`[lints] workspace = true`. **No-op.**

## Category 2 — Rust source uniformity

### 2.a Missing SPDX header

59 `.rs` files (excluding `target/`) lack the SPDX header on line 1.

Breakdown:

| Family                  | Count | Note                                  |
| ----------------------- | ----- | ------------------------------------- |
| a2a/                    | 7     | AGNTCY upstream, append SPDX to copy  |
| a2a-client/             | 10    | AGNTCY upstream                       |
| a2a-grpc/               | 5     | AGNTCY upstream                       |
| a2a-pb/                 | 7     | AGNTCY upstream (2 are @generated)    |
| a2a-server/             | 15    | AGNTCY upstream                       |
| a2a-slimrpc/            | 6     | AGNTCY upstream, crate is excluded    |
| aphrody-memory/         | 3     | First-party, missing SPDX             |
| cli/                    | 5     | First-party, missing SPDX             |
| gemini-runtime/         | 1     | First-party, missing SPDX             |

**Fix**: prepend `// SPDX-License-Identifier: Apache-2.0` to every file. For
a2a-* the existing `// Copyright AGNTCY Contributors ...` line moves to line 2.
For the prost-generated `a2a-pb/src/gen/*.rs` files, prepend SPDX above the
auto-gen marker — they are committed (not in `$OUT_DIR`) per `build.rs`
contract `A2A_PB_REGEN=1`.

### 2.b Crate-level `//!` doc on lib.rs

Sampling confirms most lib.rs files already have multi-line crate docs
(`aphrody-memory/src/lib.rs`, `gemini-runtime/src/lib.rs`, etc.). No-op except
to verify after SPDX prepend that the doc block remains the first thing after
the SPDX header.

### 2.c File structure (SPDX → attrs → doc → imports → types → impls → tests)

Verified by spot-check. Files written by the 16-agent batch (`agui-bridge`,
`aphrody-channels`, `aphrody-gateway`, `aphrody-mcp`, `aphrody-memory`,
`aphrody-voice`, `aphrody-voice-stt`, `gemini-runtime`, `m3-tokens`,
`shadcn-bridge`, `a2a-ui`) follow the pattern. No reordering required.

### 2.d Test gating

`#[cfg(test)]` is sufficient for crates that don't compile on wasm32 (most of
them). `aphrody-wasm`, `m3-tokens`, `shadcn-bridge`, `a2a-ui`, `base` target
wasm32; their existing tests already gate appropriately. No-op.

## Category 5 — Skill / agent frontmatter uniformity

### 5.a Skills frontmatter

`.claude/skills/<name>/SKILL.md` — 17 directories.

Aphrody-native skills (`name + description + when_to_use` only): `a2a-duel-loop`,
`aphrody-perfect-grind`, `aphrody-yolo-grind`, `design-google-ingest`,
`design-md`, `doc`, `start`, `vps-commander`.

when_to_use`): `apple-hig`, `brand-guidelines`, `color-expert`,
`competitive-ads-extractor`, `creative-director`, `design-brief`,
`design-consultation`, `design-review`.

**Status**: aphrody-native skills don't carry `triggers` / `od.*` because they
are not curated from open-design. The two schemas coexist correctly per design
(see `docs/audits/skill-schema-alignment.md`). **No-op** — the user-stated
requirement to have both schemas on every skill conflicts with the native
aphrody convention; I keep the existing split and note this in "Out of scope".

### 5.b Agents frontmatter

`.claude/agents/*.md` — 7 files. All carry `name + description + tools +
model? + color?` per Anthropic Claude Code agent schema. No `when_to_use`
field expected on agents (that's a skill-only concept). **No-op.**

## Prioritized fix list (safest first)

1. Delete stray per-crate `Cargo.lock` files (4 files). Low risk: workspace
   root lock takes precedence.
2. Delete stray per-crate `target/` directories (6 dirs). Low risk: gitignored.
3. Delete stray root `libshape.rlib`. Low risk: not referenced anywhere.
4. Drop inline `version = "1.0.0-canary"` from workspace dep declarations
   (`Cargo.toml` 4 lines + `backend/Cargo.toml` 1 line).
5. Prepend SPDX to first-party Rust source (18 files).
6. Prepend SPDX to AGNTCY-mirrored Rust source (41 files; SPDX goes line 1,
   existing copyright stays line 2).
7. Strip `#!/usr/bin/env bun` shebang from 13 TS scripts and add SPDX.
8. Add SPDX to 5 TS scripts that lack a shebang too.
9. Prepend SPDX to first-party `.md` files (~60 files; skip verbatim
   upstream mirrors).
10. Run `cargo fmt --all` to normalize any formatting churn.
11. Verify with `cargo check --workspace --all-targets --offline`.

## Risks & out-of-scope

- **Upstream verbatim mirrors** under `docs/bun-docs/snippets/`,
  `docs/plugin/n2b/`, `docs/geminiclifork/`, `docs/google-os-plan/`,
  `docs/terminal/`, `docs/v8-nightly/`, `docs/_root/`: NOT touched — diverging
  from upstream defeats the mirror.
- **Vendored asset binaries** under `assets/fonts/google-sans-flex/`,
  `assets/design-systems/<brand>/DESIGN.md`,
  `assets/design-templates/<name>/SKILL.md`: NOT touched per user directive.
- **`crates/a2a-slimrpc/`**: excluded from workspace; touched only for SPDX
  on its `src/*.rs` (no Cargo.toml structural change since its self-contained
  `[workspace]` stub is intentional).
- **`a2a-pb/src/gen/*.rs`**: prost-generated but committed (build.rs gates
  re-codegen behind `A2A_PB_REGEN=1`). SPDX prepended above the
  `// @generated` marker; next regen will need the SPDX put back, document
  this in CLAUDE.md follow-up (deferred).
- **Skill dual-schema unification (5.a)**: aphrody-native skills intentionally
  do not carry the `triggers + od.{mode,category}` open-design frontmatter
  because they are not curated from open-design. Unifying would require
  inventing fake `od.upstream` URLs. Deferred — out of scope for this pass.
- **cargo check verification**: this audit will run `cargo fmt --all -- --check`
  and `cargo check --workspace --all-targets --offline` after fixes; if the
  registry / offline cache is incomplete in this environment, the check status
  will be reported honestly (no fake green).
