# @aphrody-code/theme

The **canonical aphrody UI tokens** — one source of truth for the Material 3
fusion (M3 + shadcn/ui + Tailwind v4), light and dark. Every first-party aphrody
UI imports these; no app hand-rolls colour values.

## What's in `tokens.css`

Generated by the aphrody CLI (`aphrody design tokens --fusion`):

- the M3 system palette `--md-sys-color-*` (light `:root`, dark via
  `@media (prefers-color-scheme: dark)` and a `.dark` class for a forced theme);
- the **shadcn/ui** alias block (`--background`, `--primary`, `--radius`, …)
  mapped onto the M3 vars;
- the **Tailwind v4** `@theme inline` block.

Because the shadcn and Tailwind aliases reference `var(--md-sys-color-*)`, the
dark theme only re-declares the M3 palette — the aliases follow automatically.

## Use

```ts
// In any Bun/web app — Bun bundles the CSS into the page.
import "@aphrody-code/theme/tokens.css";
```

```html
<!-- force the dark theme regardless of the OS preference -->
<html class="dark"></html>
```

Then style with the tokens, e.g. `background: var(--md-sys-color-surface)` or the
shadcn aliases `var(--background)` / `var(--primary)`.

## Regenerate

```sh
bun run generate     # runs `aphrody design tokens` + formats the output
```

`generate.ts` shells out to the `aphrody` CLI (build + deploy it from the Rust
repo, `C:\src\aphrody`), so the Rust `m3-tokens` crate stays the upstream source
of truth and this file never drifts by hand.

## Why this exists

It unifies the aphrody UI stack: `m3-react`, `console`, and any future app draw
their colours from one generated sheet instead of duplicating (or, worse,
hand-rolling) palettes. See `docs/design/` for the fusion plan.
