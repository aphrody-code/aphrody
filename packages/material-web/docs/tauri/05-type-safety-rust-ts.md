# 05. Sécurité de Types de Bout en Bout (Rust ↔ TypeScript)

Ce guide explique comment mettre en œuvre une synchronisation automatique et bidirectionnelle des types de données entre notre backend natif Rust (Tauri) et notre frontend React en exploitant la crate **`ts-rs`** intégrée à notre espace de travail.

---

## ⚙️ 1. Concept de la Synchronisation de Types

Plutôt que d'écrire et de maintenir manuellement des types TypeScript qui décrivent nos modèles Rust, nous déclarons la structure de données une seule fois côté Rust. À chaque compilation ou exécution de tests, les définitions TypeScript (`.ts`) correspondantes sont régénérées à la volée, éliminant toute dérive de types (type drift) lors de refactoring.

```
  [ Modèles Rust ]
         │ (derive TS macro)
         ▼
    cargo test
         │
         ▼
  [ Fichiers TypeScript ]
         │ (import typé)
         ▼
  [ Composants React ]
```

---

## 🛠️ 2. Étape 1 : Déclaration côté Rust (`src-tauri` ou `bun-rs`)

Prenons l'exemple d'une configuration de thème dynamique Material You envoyée par le frontend et traitée par notre backend :

Dans votre crate Rust (`packages/bun-rs/src/lib.rs` ou votre code de plugin Tauri) :

```rust
use ts_rs::TS;
use serde::{Serialize, Deserialize};

#[derive(TS, Serialize, Deserialize, Debug)]
#[ts(export)] // Indique à ts-rs d'exporter ce type
#[ts(export_to = "ThemeConfig.ts")] // Nom du fichier généré (placé dans packages/bun-rs/bindings/)
pub struct ThemeConfig {
    pub seed_color: String,
    pub dark_mode: bool,
    pub contrast_level: f64,
}
```

---

## 🔄 Étape 2 : Génération automatique des fichiers de type

Les types sont générés automatiquement par `ts-rs` sous forme de suite de tests unitaires lors de la compilation. Pour générer ou actualiser vos types :

```bash
# Se placer dans le dossier de la crate Rust
cd packages/bun-rs

# Exécuter les tests pour déclencher l'écriture des fichiers bindings/
cargo test
```

Le fichier `packages/bun-rs/bindings/ThemeConfig.ts` est généré instantanément :
```typescript
// This file was generated by [ts-rs](https://github.com/Aleph-Alpha/ts-rs). Do not edit this file manually.

export type ThemeConfig = { 
  seed_color: string, 
  dark_mode: boolean, 
  contrast_level: number, 
};
```

---

## ⚛️ Étape 3 : Consommation dans votre application React

Dans votre application frontend (ex: `examples/showcase`), importez directement les types générés et utilisez-les dans vos appels IPC :

```tsx
import React, { useState } from "react";
import type { ThemeConfig } from "../../../packages/bun-rs/bindings/ThemeConfig";

export function ThemeSyncButton() {
  const [status, setStatus] = useState<string>("Prêt");

  const sendThemeToTauri = async () => {
    // 1. Définir le modèle typé attendu par le FFI Rust
    const payload: ThemeConfig = {
      seed_color: "#6750a4",
      dark_mode: true,
      contrast_level: 0.0,
    };

    try {
      setStatus("Envoi...");
      // 2. Invocation de la commande Tauri typée
      // 'plugin:window|set_theme' ou une commande personnalisée 'apply_theme'
      await window.__TAURI_INTERNALS__?.invoke("plugin:window|set_theme", {
        value: payload.dark_mode ? "dark" : "light",
      });
      setStatus("Thème Synchronisé !");
    } catch (err) {
      setStatus(`Erreur : ${String(err)}`);
    }
  };

  return (
    <button onClick={sendThemeToTauri}>
      Synchroniser ({status})
    </button>
  );
}
```

## 🛡️ 4. Intégration en Intégration Continue (CI)

Pour s'assurer en cours de CI qu'aucun développeur n'a commis de modification Rust sans mettre à jour les types générés ou sans casser le typecheck frontend, configurez votre étape de vérification dans `turbo.json` :

```json
{
  "tasks": {
    "typecheck": {
      "dependsOn": ["^build"],
      "outputs": []
    }
  }
}
```

Et exécutez la validation globale à chaque commit :
```bash
# Vérifie la parité Rust, regénère les types, et exécute le tsc frontend
bun run build && bun run typecheck
```
